# 🤖 ربات نرخ امروز چند؟

ربات چندپیام‌رسانه‌ای (تلگرام + بله + ایتا) که نرخ‌های دلار، طلا، سکه، ارز
دیجیتال و شاخص‌های بورس را مستقیم از همان دیتابیس Turso که پروژهٔ
اسکرِیپرِ شما (`nrkhmroozchand-db`) پر می‌کند، می‌خواند.

میزبانی روی **[Railway](https://railway.com)** — یک کانتینر واقعی و
همیشه‌روشن که مستقیم از گیت‌هاب دیپلوی می‌شود و با هر `git push` خودکار
دوباره دیپلوی می‌کند.

---

## 🩹 چه چیزی در این نسخه اصلاح شد

قبل از رفتن سراغ ویژگی‌های جدید، این‌ها را در کد شما پیدا و اصلاح کردم:

1. **باگ اصلی جواب ندادن ربات:** در `bot/handlers.py` در ۳ جا به‌جای صدا
   زدن تابع درست `get_welcome_text()`، یک نام ناقص `get_()` نوشته شده بود
   که با اجرا شدن، خطا می‌داد و کل پردازش `/start` را متوقف می‌کرد.
2. یک متن هاردکد با دبل `@@nerkhemrooz_bot` در پیام جستجو، که حالا از
   `config.BOT_USERNAME` خوانده می‌شود.
3. **فایل‌های `Procfile` و `railway.json` اصلاً وجود نداشتند** — یعنی
   Railway نمی‌دانست چطور `gunicorn` را با `$PORT` درست اجرا کند. این خیلی
   محتمل است که علت اصلی «هنوز نسخهٔ قدیمی نشان می‌دهد» بوده: بدون این دو
   فایل، دیپلوی جدید شما احتمالاً درست بالا نمی‌آمده و Railway نسخهٔ قبلی
   (موفق) را نگه داشته بوده.

بعد از پوش کردن این نسخه، حتماً تب **Deployments** روی Railway را چک کنید
که آخرین دیپلوی واقعاً **Success** باشد، نه صرفاً build شده.

## 🧠 معماری در یک نگاه

```
تلگرام  --> POST /webhook       ---\
بله     --> POST /webhook/bale  ----+-->  همان اپ Flask (app.py) روی Railway
ایتا    --> (چیزی برای دریافت ندارد؛ توضیح در بخش مربوطه)
                                            |
                                            v
                     هر پیام‌رسان یک bot/handlers.py مخصوص خودش دارد
                     (bot/, bale/) که از دادهٔ مشترک (bot/db.py,
                     bot/format.py, bot/keyboards.py, bot/membership.py)
                     استفاده می‌کند بدون این‌که در آن‌ها تغییری بدهد
                                            |
                                            v
                          Turso (فقط خواندن از market_prices)
```

فایل‌های اصلی تلگرام (`bot/`) که قبلاً کار می‌کردند، دست‌نخورده مانده‌اند
(به‌جز رفع همان ۲ باگ بالا)؛ بله و ایتا کاملاً در پوشه‌های جدید و مستقل
(`bale/`, `eitaa/`) اضافه شده‌اند و هیچ‌کدام باعث نمی‌شوند تلگرام از کار
بیفتد — حتی اگر توکن بله/ایتا را اصلاً تنظیم نکنید.

### ساختار فایل‌ها

```
tgju-telegram-bot/
├── app.py                  # اپ Flask با ۲ مسیر: /webhook (تلگرام) و /webhook/bale (بله)
├── bot/                     # ربات تلگرام (همان قبلی + رفع باگ + membership.py جدید)
│   ├── config.py             # + REQUIRED_CHANNELS جدید
│   ├── membership.py          # 🆕 منطق عضویت اجباری (مشترک بین تلگرام و بله)
│   ├── db.py, format.py, keyboards.py, telegram_api.py, handlers.py
├── bale/                    # 🆕 ربات بله، کاملاً مستقل
│   ├── config.py, api.py, db.py, handlers.py
├── eitaa/                   # 🆕 اتصال ایتا (فقط ارسال؛ توضیح در بخش مربوطه)
│   ├── config.py, api.py, broadcaster.py
├── requirements.txt
├── Procfile / railway.json / .python-version   # 🆕 تنظیمات دیپلوی Railway
├── set_webhook.py           # ثبت وبهوک تلگرام
├── set_webhook_bale.py       # 🆕 ثبت وبهوک بله
└── .env.example
```

## 🔒 عضویت اجباری در کانال (Join Gate)

جدید و برای هر دو ربات تلگرام و بله فعال است.

**چطور کار می‌کند:**
1. کاربر `/start` می‌زند → پیام خوش‌آمدگویی می‌آید.
2. بلافاصله ربات عضویت کاربر را در کانال(های) `REQUIRED_CHANNELS`
   (در `bot/config.py`) چک می‌کند. اگر عضو نبود، یک پیام دوم و جدا می‌فرستد:
   *«برای استفاده از این ربات باید عضو این کانال(ها) شوید»* + دکمهٔ
   لینک کانال + دکمهٔ **«✅ عضو شدم»**.
3. تا وقتی عضو نشده، هر دکمه یا پیام دیگری که بزند، همین پیام دوباره
   نشانش داده می‌شود (خدمات اصلی قفل است).
4. با زدن «✅ عضو شدم»، ربات دوباره از تلگرام می‌پرسد؛ اگر واقعاً عضو شده،
   پیام به منوی اصلی تبدیل می‌شود.

**تنظیم کانال پیش‌فرض شما (`nerkhemroozchand`) از قبل انجام شده.** برای
افزودن کانال دوم بعداً، کافی‌ست یک دیکشنری دیگر به لیست `REQUIRED_CHANNELS`
در `bot/config.py` (برای تلگرام) یا `bale/config.py` (برای بله) اضافه کنید:
```python
REQUIRED_CHANNELS = [
    {"id": "@nerkhemroozchand", "title": "کانال نرخ امروز چند؟", "url": "https://t.me/nerkhemroozchand"},
    {"id": "@your_second_channel", "title": "کانال دوم شما", "url": "https://t.me/your_second_channel"},
]
```

### ⚠️ خیلی مهم: ربات را ادمین کانال کنید
تلگرام (و ظاهراً بله هم چون از همان الگو پیروی می‌کند) فقط زمانی به ربات
اجازهٔ `getChatMember` (بررسی عضویت دیگران) می‌دهد که **خود ربات عضو —
ترجیحاً ادمین — همان کانال باشد**. پس:
1. به کانال `@nerkhemroozchand` بروید.
2. ربات (`@nerkhemrooz_bot`) را به‌عنوان ادمین اضافه کنید (کافی‌ست حداقل
   دسترسی‌های پیش‌فرض را داشته باشد).
اگر این کار را نکنید، `getChatMember` همیشه خطا می‌دهد و ربات برای احتیاط
کاربر را «عضو نشده» در نظر می‌گیرد — یعنی هیچ‌کس نمی‌تواند از ربات استفاده
کند، حتی اعضای واقعی کانال.

## 🚀 بخش ۱: راه‌اندازی ربات تلگرام (Railway)

### ۱) ساخت ربات در تلگرام
با [@BotFather](https://t.me/BotFather)، `/newbot`، توکن را کپی کنید. برای
autofill سراسری: `/setinline`.

### ۲) پوش به گیت‌هاب
```bash
cd tgju-telegram-bot
git init && git add . && git commit -m "fix bugs + join gate + bale + eitaa"
git branch -M main
git remote add origin https://github.com/<یوزرنیم‌شما>/tgju-telegram-bot.git
git push -u origin main
```
(اگر ریپازیتوری از قبل وجود دارد، به‌جای `git init` فقط
`git add . && git commit -m "..." && git push` کافی‌ست.)

### ۳) پروژه در Railway
[railway.com](https://railway.com) → **New Project** →
**Deploy from GitHub repo** → ریپازیتوری‌تان را انتخاب کنید. با وجود
`Procfile`/`railway.json` جدید، این بار باید بیلد درست بالا بیاید.

### ۴) متغیرهای محیطی (تب Variables)
```
TELEGRAM_BOT_TOKEN=...
BOT_USERNAME=nerkhemrooz_bot
TURSO_DATABASE_URL=libsql://your-db-name.turso.io
TURSO_AUTH_TOKEN=...
WEBHOOK_SECRET=یک-رشتهٔ-تصادفی-دلخواه
```

### ۵) گرفتن دامنه و ثبت وبهوک
تب **Settings → Networking → Generate Domain**. سپس روی کامپیوتر خودتان:
```bash
pip install requests
export TELEGRAM_BOT_TOKEN="..."
export WEBHOOK_SECRET="همان مقدار قدم ۴"
python set_webhook.py https://<آدرس-پروژه‌شما>.up.railway.app/webhook
```
`/start` بزنید و تست کنید (و یادتان نرود ربات را ادمین کانال کنید، بالا
توضیح داده شد).

## 🟡 بخش ۲: راه‌اندازی ربات بله (Bale)

بله API‌ای «بر پایهٔ API بات تلگرام با تغییرات جزئی» دارد (مستندات رسمی:
docs.bale.ai)، برای همین ساختار کد تقریباً یکی است. **تفاوت مهم: بله
inline mode (autofill در چت‌های دیگر) را پشتیبانی نمی‌کند** — پس آن ویژگی
اینجا وجود ندارد؛ جستجو فقط با تایپ مستقیم داخل چت خود ربات کار می‌کند.

### ۱) ساخت بازو (ربات) در بله
در بله به `@botfather` پیام بدهید و بازوی جدید بسازید؛ توکن را کپی کنید.

### ۲) متغیرهای محیطی جدید (همان تب Variables در Railway)
```
BALE_BOT_TOKEN=...
BALE_WEBHOOK_SECRET=یک-رشتهٔ-تصادفی-دیگر
BALE_BOT_USERNAME=یوزرنیم‌بازوی‌شما
```
بعد از ذخیره، Railway خودکار redeploy می‌زند (کد بله از قبل توی همین
ریپازیتوری هست، نیازی به کار دیگری نیست).

### ۳) ثبت وبهوک بله
```bash
export BALE_BOT_TOKEN="..."
export BALE_WEBHOOK_SECRET="همان مقدار بالا"
python set_webhook_bale.py https://<آدرس-پروژه‌شما>.up.railway.app/webhook/bale
```

### ۴) ادمین کردن ربات در کانال بله
مثل تلگرام، ربات باید عضو/ادمین کانال بله‌تان (`bale/config.py` →
`REQUIRED_CHANNELS`) باشد تا بررسی عضویت کار کند.

### محدودیت شناخته‌شده
دقیقاً نام هدر مخفی وبهوک بله را در مستندات رسمی پیدا نکردم (چون این جزئیات
مستند نشده)؛ کد هم `X-Bale-Bot-Api-Secret-Token` و هم `X-Telegram-Bot-Api-Secret-Token`
را چک می‌کند. اگر بعد از تنظیم دیدید پیام‌های واقعی بله رد می‌شوند
(۴۰۳ در لاگ Railway)، ساده‌ترین راه‌حل موقت این است که `BALE_WEBHOOK_SECRET`
را خالی بگذارید (این بررسی را کلاً غیرفعال می‌کند؛ امنیتش کمتر می‌شود ولی
حداقل کار می‌کند تا جزئیات را با هم پیدا کنیم).

## 🟠 بخش ۳: اتصال ایتا (Eitaa) — با یک محدودیت واقعی

### ⚠️ این بخش با تلگرام/بله فرق اساسی دارد — حتماً بخوانید
فایل راهنمای API که فرستادید (eitaayar.ir) را کامل خواندم و در وب هم
جست‌وجو کردم. نتیجه: **API مستندشدهٔ ایتا فقط سه متد دارد: `getMe`،
`sendMessage`، `sendFile` — هر سه فقط برای ارسال هستند.** هیچ متد رسمی
برای دریافت پیام کاربران (نه webhook، نه `getUpdates`، نه polling) در این
مستندات وجود ندارد. بنابراین:
- ❌ منوی شیشه‌ای تعاملی، دکمه‌ها، دیده‌بان شخصی و جستجو **روی ایتا قابل
  ساخت نیستند** — چون ربات اصلاً نمی‌فهمد کاربر چه چیزی فرستاده یا کدام
  دکمه را زده.
- ✅ چیزی که *واقعاً* ممکن و پیاده شده: یک اسکریپت که یک «گزارش نرخ» متنی
  می‌سازد و به کانال ایتای شما پست می‌کند (شبیه یک خبرنامهٔ خودکار، نه یک
  ربات مکالمه‌ای).

اگر جایی مستندات رسمی‌تری از یک متد دریافت پیام برای ایتا پیدا کردید
(ممکن است در نسخه‌های جدیدتر اضافه شده باشد)، برایم بفرستید تا این بخش را
به یک ربات کاملاً تعاملی مثل تلگرام/بله ارتقا بدهم.

### راه‌اندازی
۱) توکن API را از پنل [eitaayar.ir](https://eitaayar.ir) بگیرید.
۲) در تب Variables روی Railway:
```
EITAA_TOKEN=...
EITAA_CHAT_ID=nerkhemroozchand
```
۳) اجرای دستی (مثلاً از کنسول Railway یا لوکال):
```bash
python -m eitaa.broadcaster cur     # گزارش ارزهای اصلی
python -m eitaa.broadcaster gld     # گزارش طلا/سکه
python -m eitaa.broadcaster cry     # گزارش ارز دیجیتال
```
(کدهای دسته را از `bot/config.py` → `CATEGORIES` و `BOURSE_SUBCATEGORIES`
بردارید: `cur`, `gld`, `cry`, `bir`, `bwd`, `cmd`.)

۴) **برای ارسال خودکار و زمان‌بندی‌شده**، دقیقاً مثل پروژهٔ اسکرِیپر خودتان
می‌توانید یک GitHub Actions cron جدا بسازید که هر چند ساعت
`python -m eitaa.broadcaster cur` را اجرا کند، یا از قابلیت **Cron Jobs**
خود Railway (تب جدید در پروژه) استفاده کنید.

## ➕ اضافه کردن نماد جدید به منوها
کافی‌ست `symbol_key` را به یکی از لیست‌های `bot/config.py` اضافه کنید —
هم تلگرام، هم بله، هم گزارش‌های ایتا خودکار همان لیست‌ها را می‌خوانند.

## 🔧 عیب‌یابی سریع
- **تلگرام جواب نمی‌دهد:** `curl https://api.telegram.org/bot<TOKEN>/getWebhookInfo`
  → چک کنید `url` درست است و `last_error_message` خالی است.
- **دیپلوی Railway fail می‌شود:** تب Deployments → Build/Deploy Logs.
- **عضویت همیشه «رد» می‌شود حتی برای اعضای واقعی:** ربات را ادمین کانال
  نکرده‌اید؛ بالا توضیح داده شد.
- **دکمه‌ها کار نمی‌کنند ولی پیام اول می‌آید:** `WEBHOOK_SECRET`/`BALE_WEBHOOK_SECRET`
  بین Variables و اسکریپت `set_webhook*.py` یکی نیست.
- **بله وبهوکش را قبول نمی‌کند:** بخش محدودیت شناخته‌شدهٔ بله را بالا
  ببینید.
